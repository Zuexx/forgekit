# Portable AI Workflow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make this repository's documented AI workflow arrive operational in any clone, and provide a command that proves it is.

**Architecture:** Three CLIs move from global npm installs into a root `package.json`. The CodeGraph MCP server and the Superpowers plugin move from `~/.claude/` into tracked `.mcp.json` and `.claude/settings.json`. A new `scripts/preflight.sh` verifies all of it, judging the workflow config by reading its values back rather than by comparing version strings.

**Tech Stack:** bash, pnpm, Node 24, `@fission-ai/openspec`, `@colbymchenry/codegraph`, `grillme`.

## Global Constraints

- Root package is tooling-only. `app/package.json` and `app/pnpm-lock.yaml` MUST NOT change.
- `.mcp.json` MUST invoke `./node_modules/.bin/codegraph`, never `npx` — `npx` fetches from the registry when the local binary is absent, hiding the failure this change exists to surface.
- Version declarations, verbatim: `"@fission-ai/openspec": "^1.9.0"`, `"@colbymchenry/codegraph": "^1.5.0"`, `"grillme": "latest"`.
- `preflight.sh` MUST run every check before exiting, so one failure does not hide the rest. Use `set -uo pipefail`, never `set -e`.
- `preflight.sh` MUST NOT be wired into `ci.yml` or into `verify.sh`'s check list by this plan.
- Every commit message follows Conventional Commits (`docs/api/COMMIT_CONVENTION.md`).

### Task 5: Preflight — tools, config, index, hooks

**Files:**
- Create: `scripts/preflight.sh`

**Interfaces:**
- Produces: `pass()` and `fail()` helpers and the `FAILED` accumulator that Task 6 extends.

The probe-change technique in Step 3 was verified before this plan was written: `openspec new change` followed by `instructions proposal|apply --json` returns `rules=5` and `guidance=7`, and removing the probe directory leaves `git status` unchanged.

- [ ] **Step 1: Create the script skeleton with the reporting helpers**

```bash
#!/usr/bin/env bash
# Reports whether this repository's documented AI workflow is operational on this machine.
# Every check runs before exiting, so one failure does not hide the rest — hence no `set -e`.
set -uo pipefail

ROOT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
BIN_DIR="$ROOT_DIR/node_modules/.bin"
FAILED=0

pass() { printf '  ok    %s\n' "$1"; }
fail() { printf '  FAIL  %s\n        fix: %s\n' "$1" "$2"; FAILED=1; }
```

- [ ] **Step 2: Add the declared-tools check**

```bash
echo "==> Declared tools"
for tool in openspec codegraph grillme; do
  if [ -x "$BIN_DIR/$tool" ]; then
    pass "$tool"
  else
    fail "$tool is not installed" "pnpm install"
  fi
done
```

- [ ] **Step 3: Add the config-readback check**

```bash
echo "==> Workflow configuration"
if [ ! -x "$BIN_DIR/openspec" ]; then
  fail "cannot read workflow configuration" "pnpm install"
else
  probe="preflight-probe-$$"
  probe_dir="$ROOT_DIR/openspec/changes/$probe"
  trap 'rm -rf "$probe_dir"' EXIT
  if "$BIN_DIR/openspec" new change "$probe" >/dev/null 2>&1; then
    rules=$("$BIN_DIR/openspec" instructions proposal --change "$probe" --json 2>/dev/null \
      | node -pe 'JSON.parse(require("fs").readFileSync(0,"utf8")).rules?.length ?? 0' 2>/dev/null || echo 0)
    guidance=$("$BIN_DIR/openspec" instructions apply --change "$probe" --json 2>/dev/null \
      | node -pe 'JSON.parse(require("fs").readFileSync(0,"utf8")).operationGuidance?.length ?? 0' 2>/dev/null || echo 0)
    rm -rf "$probe_dir"
    if [ "$rules" -gt 0 ]; then
      pass "proposal rules readable ($rules)"
    else
      fail "openspec/config.yaml yields no proposal rules" \
           "check rules: in openspec/config.yaml — a plain scalar containing ': ' silently empties the block"
    fi
    if [ "$guidance" -gt 0 ]; then
      pass "apply guidance readable ($guidance)"
    else
      fail "openspec/config.yaml yields no apply guidance" \
           "check operations.apply.guidance in openspec/config.yaml"
    fi
  else
    fail "openspec could not create a probe change" "run: $BIN_DIR/openspec new change probe"
  fi
fi
```

The count is what matters, not the version string. A config that parses cleanly but produces zero rules is the failure this repository has already experienced.

- [ ] **Step 4: Add the index-freshness check**

```bash
echo "==> CodeGraph index"
INDEX="$ROOT_DIR/.codegraph/codegraph.db"
if [ ! -f "$INDEX" ]; then
  fail "no CodeGraph index" "$BIN_DIR/codegraph index"
else
  index_epoch=$(stat -f %m "$INDEX" 2>/dev/null || stat -c %Y "$INDEX")
  head_epoch=$(git -C "$ROOT_DIR" log -1 --format=%ct)
  if [ "$index_epoch" -lt "$head_epoch" ]; then
    fail "index is older than HEAD — impact analysis from it would be out of date" \
         "$BIN_DIR/codegraph index"
  else
    pass "index present and not older than HEAD"
  fi
fi
```

`stat -f %m` is macOS, `stat -c %Y` is GNU; the fallback covers both.

- [ ] **Step 5: Add the hooks check and the exit**

echo

### Task 6: Preflight — cited capabilities resolve

**Files:**
- Modify: `scripts/preflight.sh` — insert before the final exit block

**Interfaces:**
- Consumes: `pass`, `fail`, `BIN_DIR`, `ROOT_DIR` from Task 5.

The check must catch a citation like `grilling`, which is a bare word with no prefix — pattern-matching only `superpowers:*` and `/opsx:*` would miss exactly the defect that motivated this change. So the rule is inverted: **any backticked token in the `Use` column of the overlapping-skills table that is not recognised is a failure.**

- [ ] **Step 1: Write the check to fail against the current AGENTS.md**

Insert into `scripts/preflight.sh` before the final `echo`:

```bash
echo "==> Capabilities cited by workflow instructions"
PLUGIN_SKILLS=$(ls -d "$HOME"/.claude/plugins/cache/*/superpowers/*/skills 2>/dev/null | head -1)

if [ -z "$PLUGIN_SKILLS" ]; then
  fail "Superpowers plugin is not installed" \
       "open Claude Code in this repository and approve the plugin declared in .claude/settings.json"
fi

# Tokens cited in the "Use" column of the overlapping-skills table, plus every structured
# capability literal anywhere in the two instruction files.
cited=$(
  {
    awk -F'|' '/^\| [A-Z]/ && NF>3 { print $3 }' "$ROOT_DIR/AGENTS.md"
    grep -ohE '`(superpowers:[a-z-]+|/opsx:[a-z]+)`' \
      "$ROOT_DIR/AGENTS.md" "$ROOT_DIR/openspec/config.yaml"
  } | grep -oE '`[^`]+`' | tr -d '`' | sort -u
)

while IFS= read -r cap; do
  [ -z "$cap" ] && continue
  case "$cap" in
    superpowers:*)
      if [ -n "$PLUGIN_SKILLS" ] && [ -d "$PLUGIN_SKILLS/${cap#superpowers:}" ]; then
        pass "$cap"
      elif [ -n "$PLUGIN_SKILLS" ]; then
        fail "$cap does not resolve" "correct the skill name in AGENTS.md or openspec/config.yaml"
      fi
      ;;
    /opsx:*)
      if [ -f "$ROOT_DIR/.claude/commands/opsx/${cap#/opsx:}.md" ]; then
        pass "$cap"
      else
        fail "$cap does not resolve" "correct the command name in AGENTS.md"
      fi
      ;;
    /code-review)      pass "$cap (built-in)" ;;
    codegraph_explore)
      if grep -q '"codegraph"' "$ROOT_DIR/.mcp.json" 2>/dev/null; then
        pass "$cap"
      else
        fail "$cap has no declared MCP server" "declare codegraph in .mcp.json"
      fi
      ;;
    grillme)
      if [ -x "$BIN_DIR/grillme" ]; then
        pass "$cap"
      else
        fail "$cap does not resolve" "pnpm install"
      fi
      ;;
    *)
      fail "unrecognised capability \`$cap\`" \
           "it resolves to nothing — correct it in AGENTS.md, or add it to the toolchain"
      ;;
  esac
done <<CITED
$cited
CITED
```

Skipping the `superpowers:*` arm when `PLUGIN_SKILLS` is empty is deliberate: a missing plugin is reported once as its own cause, not six times as its symptoms.

This is the point of the task: the check earns its place by catching a real defect that has been in the repository unnoticed. Do not fix `AGENTS.md` yet — that is Task 8, and it must be shown to turn this red check green.
